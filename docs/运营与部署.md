# SnowOn Terminal — 架构、功能、待办与服务器部署

Robinhood Chain 上的发射平台聚合交易终端。首个接入平台是 **snowon.fun**：毕业前走绑定曲线直购，毕业后自动路由到 Uniswap V4 池（必须走 `SnowSwapRouter`，标准 Universal Router 无法结算 hook 的 in-swap fee）。

本文说明：系统怎么拼在一起、每个功能做什么、上线前必须填什么、还没做完什么、以及怎么部署到服务器。

---

## 1. 整体架构

三个常驻进程 + 一套 Postgres + 一套 Redis。Web 不直连链上做列表/K 线，链上事件由 indexer 落库后再被 API 读出。

```
                    ┌─────────────────────────────────────────┐
                    │              浏览器 / 钱包               │
                    │  发现页 · 代币页 · 管理页 · Privy 登录    │
                    └───────────┬─────────────────┬───────────┘
                                │ HTTP            │ WebSocket
                                ▼                 ▼
                     ┌─────────────────┐   ┌──────────────┐
                     │  apps/web       │   │  apps/chat   │
                     │  Next.js :3000  │   │  WS :8080    │
                     │  页面 + /api/*  │   │  聊天/价格扇出│
                     └────────┬────────┘   └──────┬───────┘
                              │                   │
                              │     ┌─────────────┤
                              │     │  pub/sub    │
                              ▼     ▼             ▼
                     ┌─────────────────┐   ┌──────────────┐
                     │  PostgreSQL     │   │  Redis       │
                     │  业务库 terminal │   │  扇出 + 叮住 │
                     └────────▲────────┘   └──────▲───────┘
                              │ 写入              │ publish price:*
                     ┌────────┴────────┐          │
                     │  apps/indexer   │──────────┘
                     │  回填 + 实时索引 │
                     └────────▲────────┘
                              │ eth_getLogs / eth_call
                              ▼
                     ┌─────────────────┐
                     │  链 RPC / WS    │
                     │  Factory/Curve  │
                     │  PoolManager    │
                     └─────────────────┘
```

### 1.1 仓库结构

| 路径 | 角色 |
|------|------|
| `apps/web` | Next.js 前端 + BFF API（发现、代币、K 线 UDF、报价、构交易、持有者、安全、管理） |
| `apps/indexer` | 链上事件索引：创建 / 买卖 / 毕业 / V4 Swap → `trades` / `positions` / `latest_prices` / `bundle_scores` |
| `apps/chat` | WebSocket：聊天落库、价格 tick 扇出、叮住消息、弹幕 |
| `packages/db` | Drizzle schema + 迁移。所有业务表带 `chain_id`（BSC 预留） |
| `packages/adapters` | `LaunchpadAdapter`：线性曲线本地报价、买卖 calldata、毕业检测、V4 路由 |
| `tools/` | 本地 PG+Redis 启动、截图/联调脚本 |

### 1.2 运行时数据流

1. **回填**：indexer 从 `deployBlock` 或游标 `indexer_cursors.last_block` 扫到链头。`CoinCreated` 写入 `tokens`，Buy/Sell/Swap 写入 `trades`，滚动更新 `positions`（加权平均成本）和 `latest_prices`。
2. **实时**：indexer 用 `watchEvent` 继续收日志，把 `price:{chainId}:{token}` 发到 Redis；chat 进程 `psubscribe` 后扇出给已加入该房间的浏览器。
3. **发现页**：`GET /api/tokens` 读 `tokens + latest_prices + bundle_scores + positions`，2 秒内存缓存。
4. **K 线**：`GET /api/udf/history` 按周期聚合 `trades.price_eth`（毕业前后同一套 ETH 计价，无缝拼接）。有 WS 时前端续画最后一根 bar，HTTP 作兜底。
5. **交易**：浏览器 → `/api/quote`（本地曲线数学 / 池 subspot）→ `/api/build-tx` 返回 calldata → Privy/外部钱包签名广播。indexer 随后索引到这笔成交。
6. **聊天**：浏览器连 `NEXT_PUBLIC_WS_URL`，`join` 房间 `{chainId}:{token}` 或 `{chainId}:global`。消息进 `chat_messages`，叮住进 Redis sorted set。

### 1.3 数据表（Postgres）

| 表 | 用途 |
|----|------|
| `tokens` | 代币元数据、曲线参数、毕业状态、`pool_id`、社交链接 |
| `trades` | 每笔成交（curve / pool），ETH 计价均价 |
| `latest_prices` | 最新价、毕业进度快表（榜单用） |
| `positions` | 钱包×代币持仓、成本、已实现盈亏、买卖次数 |
| `wallets` | 地址库：`first_funder`、`funder_label`、启发式 `labels` |
| `bundle_scores` | 捆绑/老鼠仓综合分（0–100） |
| `chat_users` / `chat_messages` | 聊天用户与消息（软删审核） |
| `indexer_cursors` | 每条链扫到的最后区块 |
| `chain_configs` | 管理面板可改的工厂/RPC 配置（DB 权威；indexer 启动仍读 env） |

大额整数一律 `numeric`，JS 侧用 bigint 字符串进出，避免精度丢失。

## 2. 功能详解

### 2.1 发现页 `/`

四栏 + 公共聊天（移动端底部 Tab）：

| 栏目 | 规则 |
|------|------|
| 异动代币 | 已毕业，按 24h 涨幅排序 |
| 新创建 | 未毕业，按创建时间倒序 |
| 即将毕业 | 未毕业且进度 > 0，按毕业进度倒序 |
| 毕业代币 | 已毕业，按毕业时间倒序 |
| 公共聊天室 | 房间 `{chainId}:global`，顶部叮住条 |

每张代币卡：火花线、24h 涨幅、美元市值（ETH×Binance 价）、毕业进度条、Top10 / 捆绑 / 钓鱼占比（颜色预警）、社交图标、收藏星标。

顶部：搜索（代币名 / 合约 / 钱包）、AI 快捷问答（规则引擎，不是大模型）、资产面板、钱包登录。底部：钱包追踪 + ETH 价格。

### 2.2 代币页 `/token/[address]`

- 信息条：logo、名称、合约复制、antiBundle / 毕业 / 捆绑分徽章、社交、现价与 24h 涨幅。
- PNL 分享卡：当前钱包在该币的未实现+已实现盈亏，一键复制战报。
- 时段成交量条：1m / 5m / 15m / 1h / 4h / 1D，点击同步 K 线周期。
- K 线：lightweight-charts，数据 `/api/udf/history`，WS `price:*` 续画；可叠弹幕。
- 买卖面板：报价 + 构造交易；滑点/Gas 档位本地保存；antiBundle 未毕业仅 EOA。
- **持有者面板（本轮加强）**：
  - Top20 持仓、占比、销毁地址。
  - **成本价**：剩余持仓的加权平均买入价（`cost_basis_eth / balance`，ETH/枚）。
  - **盈亏金额**：未实现（现价×余额 − 剩余成本）+ 已实现，绿色盈利 / 红色亏损，附收益率。
  - **同资金来源**：该代币当前持仓里 `first_funder` 相同且 ≥ 2 个地址 → 行左侧**红色虚线** + 淡红斜纹底。
  - **钓鱼**：`funder_label=mixer` 或 labels 含 phish/scam/mixer → 红色「钓」。
  - **捆绑**：同资金来源簇，或 labels 含 bundler/bundle/sniper → 红色「捆」。
- 聊天室：房间 `{chainId}:{token}`，持仓徽章（可关）。
- 合约安全：Blockscout 是否开源、毕业后 LP 永久锁定（SnowLaunchHook 拒撤流动性）。

### 2.3 交易路径

**毕业前**

- 买：`ETH → SnowBondingCurve.buy(minOut)`，合约内部换 Q 再沿线性曲线铸币。
- 卖：先 `approve` 曲线，再 `sell`。
- 报价：`packages/adapters` 用 `p0/slope/sold` 本地计算，不依赖 Multicall3。

**毕业后**

- 一律 `SnowSwapRouter.swapExactIn`（ETH↔[ETH/Q]↔TOKEN/Q）。
- indexer 听 PoolManager `Swap`，`quoteAsset == 0x0`（原生 ETH）的池写入 `trades.phase='pool'`。

### 2.4 索引与风控

- 事件：`CoinCreated` / `Buy` / `Sell` / `Graduated` / V4 `Swap`。
- PNL：买入加仓加成本；卖出按比例结转成本，差额进已实现盈亏。
- 捆绑分（定时重算）：启动 5 块买入占比、同 firstFunder 簇、creator 自买、Top10 持仓，加权 0–100。
- 链下元数据：snowon Pinata 列表 + IPFS JSON（简介/社交/logo），不挡代币页首屏。

### 2.5 聊天 / 叮住 / 弹幕

| 能力 | 规则 |
|------|------|
| 文本消息 | 每用户 1 条/秒，最长 500 字，`clientMsgId` 幂等 |
| 叮住 | 20U / 2 分钟，每房间最多 5 条，Redis ZSET，顶部炫彩轮换 |
| 弹幕 | 5U / 条，飘过 K 线，不落库，3 秒限流 |
| 鉴权 | 配了 `PRIVY_APP_SECRET` 则校验 JWT；否则开发模式信任客户端 `userId` |
| 审核 | `deletedAt` 软删 |

支付：`PIN_REQUIRE_PAYMENT=1` / `DANMAKU_REQUIRE_PAYMENT=1` 时要求带 `payTxHash`。**链上验付尚未实现**，目前只记录哈希。

### 2.6 管理页 `/admin`

钱包地址命中 `NEXT_PUBLIC_ADMIN_WALLETS` 才显示入口。写接口校验 `x-admin-wallet` ∈ `ADMIN_WALLETS`。可改每条链的 RPC、工厂、hook、router、PoolManager、起始块。改完后 **indexer 必须重启**（它启动时读 env，不热加载 DB 配置）。

### 2.7 HTTP API 一览

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/tokens` | 发现页列表 |
| GET | `/api/token/:addr` | 代币详情 + 捆绑分 |
| GET | `/api/token/:addr/stats` | 分时段买/卖量 |
| GET | `/api/token/:addr/holders` | 持有者 + 成本/盈亏 + 风险标记 |
| GET | `/api/token/:addr/security` | 开源 / LP 锁 |
| GET | `/api/search?q=` | 名称或 0x 地址 |
| GET | `/api/quote` | 买/卖报价 |
| POST | `/api/build-tx` | 返回待签名交易数组 |
| GET | `/api/portfolio?address=` | 钱包持仓估值 |
| GET | `/api/wallet-activity?address=` | 最近成交 |
| GET | `/api/eth-price` | ETH/USDT（Binance，15s 缓存） |
| GET | `/api/udf/*` | K 线 UDF（config/symbols/history/time） |
| GET/PUT/POST | `/api/admin/chains` | 链配置 |

## 3. 需要填写的配置（上线前必做）

环境变量分三处（dotenv 按进程工作目录读，Next 只读 `apps/web/.env.local`）：

- 仓库根 `.env`（indexer / chat 可软链或复制）
- `apps/indexer/.env`
- `apps/chat/.env`
- `apps/web/.env.local`

生产建议同一套值，按进程拆文件即可。

### 3.1 必填

| 变量 | 填到 | 说明 |
|------|------|------|
| `ENABLED_CHAINS` | indexer | 逗号分隔 chainId，例如 `4663` |
| `RPC_URL_4663` | indexer / web | 稳定 HTTP RPC。该网关 **禁止 JSON-RPC batch**（已在代码里关掉） |
| `WS_URL_4663` | indexer（可选） | 有则 indexer 用 WS 订阅事件 |
| `SNOWON_FACTORY_4663` | indexer / 种子 | 发射工厂 |
| `SNOWON_HOOK_4663` | 种子 / 管理面板 | SnowLaunchHook |
| `SNOWON_REGISTRY_4663` | 种子 | 曲线参数 registry |
| `SNOWON_SWAP_ROUTER_4663` | 种子 / 报价 | 毕业后唯一合法 router |
| `SNOWON_POOL_MANAGER_4663` | indexer | Uniswap V4 PoolManager |
| `SNOWON_DEPLOY_BLOCK_4663` | indexer | 工厂部署块，回填起点 |
| `DATABASE_URL` | 三个进程 | `postgres://user:pass@host:5432/terminal` |
| `REDIS_URL` | indexer + chat | `redis://host:6379` |
| `NEXT_PUBLIC_CHAIN_ID` | web | 前端默认链，通常 `4663` |
| `NEXT_PUBLIC_RPC_URL` | web | 钱包/wagmi 用的 RPC |
| `NEXT_PUBLIC_WS_URL` | web | 浏览器连聊天，生产用 `wss://chat.你的域名` |
| `NEXT_PUBLIC_PRIVY_APP_ID` | web | [privy.io](https://privy.io) 应用 ID |
| `PRIVY_APP_ID` + `PRIVY_APP_SECRET` | chat | **生产必须配**，否则任何人可冒充 userId 发言 |
| `ADMIN_WALLETS` | web 服务端 | 管理写接口白名单，逗号分隔 0x 地址 |
| `NEXT_PUBLIC_ADMIN_WALLETS` | web | 前端是否显示「管理」入口（可与上面同一串） |

合约地址以 snowon.fun 在 Robinhood Chain 的实测部署为准，不要用 `.env.example` 里的全 0 占位。

### 3.2 建议填

| 变量 | 默认 | 说明 |
|------|------|------|
| `CHAT_WS_PORT` | `8080` | chat 监听端口 |
| `NEXT_PUBLIC_CHAIN_ID` | `4663` | 与 ENABLED_CHAINS 第一条一致 |
| `SNOWON_PINATA_URL` | snowon.fun/api/pinata | 链下 meta 列表 |
| `SNOWON_IPFS_GATEWAY` | ipfs.snowon.fun | meta JSON 网关 |
| `PIN_REQUIRE_PAYMENT` | 未设=开发直通 | 设 `1` 后叮住必须带 `payTxHash`（仍未链上验） |
| `DANMAKU_REQUIRE_PAYMENT` | 未设=开发直通 | 设 `1` 后弹幕必须带 `payTxHash` |

### 3.3 填写检查清单

- [ ] 官方/自建 RPC 可用，`eth_getLogs` 能扫 1–1.5 万块；确认 **不支持 Multicall3** 时走现有并行 `eth_call`
- [ ] 五个合约地址 + `SNOWON_DEPLOY_BLOCK` 与区块浏览器一致
- [ ] Postgres 已建库 `terminal`，跑过 `pnpm db:migrate`（含 `0004_perf_indexes`）
- [ ] Redis 可 `PING`
- [ ] Privy 生产：App ID + Secret；登录方式 Google / X / 钱包
- [ ] `NEXT_PUBLIC_WS_URL` 是 **wss** 且反代到 chat 8080
- [ ] 管理员钱包写入 `ADMIN_WALLETS`（服务端）和 `NEXT_PUBLIC_ADMIN_WALLETS`（前端）
- [ ] 防火墙：只对公网开 443；3000/8080/5432/6379 不直接暴露
- [ ] indexer 能从游标追到链头，发现页出现真实代币而不是空列表

## 4. 还没做完的事情

按对上线的影响排序。

### 4.1 上线前必须处理

| 项 | 现状 | 建议 |
|----|------|------|
| Privy 服务端鉴权 | 未配 Secret 时聊天信任客户端 userId | 生产必须配 `PRIVY_APP_SECRET` |
| 管理接口鉴权 | 只认请求头钱包地址，可伪造 | 改成 Privy access token 验签 |
| 叮住/弹幕验付 | 只检查哈希是否存在 | 接支付合约后校验 `payTxHash` 金额与收款人 |
| RPC 质量 | 网关 batch 会丢包；`trace_filter` 多数节点没有 | 准备付费节点；资金来源回填否则同资金来源红虚线会很少 |
| 进程守护 | 本地 `pnpm dev:*` | 用 systemd / docker compose 保活 + 日志 |

### 4.2 功能缺口（代码里已标明或能力不完整）

| 项 | 位置 | 说明 |
|----|------|------|
| 毕业后非 ETH 报价资产 | `handlers.onPoolSwap` | `quoteAsset != 0x0` 的池 Swap **直接丢弃**，K 线/PNL 缺毕业后成交。需要 ETH/Q 汇率把 Q 腿换成 ETH |
| 资金来源打标任务 | `wallets.funder_label` / `labels` | 设计了 cex/bridge/mixer/eoa，**没有离线任务往里写**。钓鱼红标目前几乎只靠 mixer 标签或手工 labels；捆绑红标主要靠 `first_funder` 聚类 |
| `first_funder` 回填 | `funding.ts` | 依赖 `trace_filter`（非标准）。RPC 不支持则簇为空，持有者红虚线不出现 |
| Transfer 未索引 | positions | 毕业后钱包互转不进 indexer，持仓/持有者徽章会偏 |
| AI | `AiPanel` | 规则引擎看榜单，不是 LLM。README 里的 MCP 包装 `/api/token`、钱包 PNL 未做 |
| BSC | adapter 注释 | 预留 chain 56。需要 `ChainConfig` + `SnowOnBsc`（bsc/bscv4 合约差异） |
| Gas 档位 | TradePanel | 只存在本地偏好，没有写入 `eth_sendTransaction` 的 gas 参数 |
| 管理改配置热加载 | indexer | 改 DB 后必须重启 indexer |
| 聊天审核后台 | `softDelete` 已导出 | 没有管理 UI 调删除 |
| 用户改名/头像/关持仓徽章 | `chat_users` 有字段 | 没有设置页 |

### 4.3 已知限制（不是 bug，但是产品边界）

- 曲线总量按 10 亿枚算市值，与合约恒定总量一致。
- 持有者成本是 **剩余仓位的加权平均成本**，不是历史每一笔的列表。
- 同资金来源只在「该代币当前仍持仓」的地址里聚类；已清仓的捆绑地址不会出现在列表里。
- K 线回看窗口有上限（例如 1m 约 3 天），不是创世到现在每一根。
- 发现页最多 200 个最近创建的代币。

## 5. 部署到服务器

推荐一台 4 核 8GB、系统盘 40GB+ 的 Linux（Ubuntu 22.04/24.04）。Node **≥ 20**，pnpm 9。

### 5.1 拓扑

```
Internet
   │
   ▼
Nginx :443
   ├─ /            → 127.0.0.1:3000   (Next.js)
   └─ /ws          → 127.0.0.1:8080   (chat WebSocket, 升级协议)
独立不反代:
   indexer 进程
   postgres :5432  (只监听 localhost 或内网)
   redis    :6379  (只监听 localhost)
```

`NEXT_PUBLIC_WS_URL` 填 `wss://你的域名/ws`（或单独子域 `wss://chat.你的域名`）。

### 5.2 安装依赖

```bash
# Node 20
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs build-essential git

# pnpm
corepack enable
corepack prepare pnpm@9.15.0 --activate

# Postgres 16 + Redis
sudo apt-get install -y postgresql postgresql-contrib redis-server
sudo systemctl enable --now postgresql redis-server
```

### 5.3 建库

```bash
sudo -u postgres psql <<'SQL'
CREATE USER terminal WITH PASSWORD '换成强密码';
CREATE DATABASE terminal OWNER terminal;
GRANT ALL PRIVILEGES ON DATABASE terminal TO terminal;
SQL
```

`postgresql.conf` 可把 `max_connections` 留默认（100）。三个 Node 进程各自连接池约 8。

### 5.4 拉代码与环境变量

```bash
sudo useradd -m -s /bin/bash snowon
sudo mkdir -p /opt/snowon-terminal
sudo chown snowon:snowon /opt/snowon-terminal
sudo -u snowon git clone <你的仓库> /opt/snowon-terminal
cd /opt/snowon-terminal
sudo -u snowon pnpm install --frozen-lockfile
```

写环境文件（示例，按 3.1 填实值）：

`/opt/snowon-terminal/.env`

```
ENABLED_CHAINS=4663
RPC_URL_4663=https://你的RPC
WS_URL_4663=wss://你的WS
SNOWON_FACTORY_4663=0x...
SNOWON_HOOK_4663=0x...
SNOWON_REGISTRY_4663=0x...
SNOWON_SWAP_ROUTER_4663=0x...
SNOWON_POOL_MANAGER_4663=0x...
SNOWON_DEPLOY_BLOCK_4663=123456
DATABASE_URL=postgres://terminal:强密码@127.0.0.1:5432/terminal
REDIS_URL=redis://127.0.0.1:6379
CHAT_WS_PORT=8080
PRIVY_APP_ID=clxxxxxxxx
PRIVY_APP_SECRET=xxxxxxxx
```

### 5.7 Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name 你的域名;

    ssl_certificate     /etc/letsencrypt/live/你的域名/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

若 chat 不挂在 `/ws` 而用独立子域，把 `location /ws` 换成该 server 的 `/`，并保证 `NEXT_PUBLIC_WS_URL` 与之一致。**`NEXT_PUBLIC_*` 在 `pnpm --filter web build` 时打进包，改完必须重新 build。**

证书：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
```

### 5.8 Docker Compose 备选

若不想在宿主机装 PG/Redis，可用 compose 只跑数据层，三个 Node 仍 systemd；或全部容器化。要点：

- Postgres 16+，volume 持久化，`POSTGRES_DB=terminal`
- Redis 6+，不必开外网端口
- web 构建参数带齐全部 `NEXT_PUBLIC_*`
- indexer 需要能访问公网 RPC
- 三个服务共用同一 `DATABASE_URL` / `REDIS_URL`

### 5.9 上线后验证

## 7. 关键设计约束（改代码时别打破）

1. 毕业后交易必须走 SnowSwapRouter，不能用 Universal Router。
2. RPC HTTP batch 必须关闭。
3. 链上无 Multicall3：adapter 用并行单次 `eth_call`。
4. 聊天必须平台可删，所以在 Postgres，不在 IPFS。
5. `trades.price_eth` 全程 ETH，K 线才能跨毕业点连续。
6. antiBundle 未毕业只允许 EOA；Privy 嵌入式钱包是 EOA，4337 会被拒。
7. Next.js 多路由会拆包，DB 连接必须挂 `globalThis`，否则打满连接。
